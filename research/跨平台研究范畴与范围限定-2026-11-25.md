# 跨平台研究范畴与测试范围限定

2026-11-25。本文补充并收窄既有实验协议；它不是新实验结论，也不把代码适配当作效果证据。TACT（当前包名 `budgetmas`，对外名 TACT-GUI）的核心问题是：**预算约束引导的多智能体自适应协作测试方法**。被测对象是 Android GUI 与 WebUI 两类有状态图形界面；多智能体指测试侧的执行、复核、诊断与调度角色，不指被测应用内部的多个 agent。

## 1. 研究问题与单位

主问题保持不变，见 [下一轮科研实验协议](下一轮科研实验协议-2026-11-24.md)：在候选测试目标多于总预算可覆盖的条件下，依据决策前可见状态与剩余额度，动态分配「继续单角色 / 自我复核 / 独立诊断 / 停止」，是否比配置充分的单角色、固定协作和强规则基线确认更多经独立核验、去重的测试目标。

新增的跨平台维度回答一个更窄的问题：**这种取舍是否依赖特定 GUI 平台，还是能在 Android 与 Web 上用同一套动作语言、预算账本、配对协议和判定口径测量。** 它不主张方法对所有软件测试有效，也不把跨平台的样本数直接相加当作同一个分布。

三层数据单位沿用 [框架与数据集调研规划](框架与数据集调研规划-2026-11-20.md)：① 应用/版本/任务及可运行环境是 benchmark；② 一次 campaign 是初始状态、任务池、预算、策略、平台与种子；③ 逐步状态、动作、成本、结果构成轨迹。应用家族仍是最小的独立统计聚类；同一 Web 站点的不同页面、同一 Android 应用的不同任务、同一缺陷的修复前后版本不得跨训练/验证/测试集拆分。

## 2. 范围内：Android GUI Testing

纳入：专用 Android 模拟器上的可恢复 GUI 功能任务；固定 APK/系统包版本、语言、布局、启动状态与入口 Activity；通过 ADB 截图、UIAutomator 层级和受限 `computer_use` 动作执行；终态由独立于执行角色的 UI 断言核验，并在干净状态重放动作序列。当前端点是**功能任务完成与保持达标状态**。已有 Round 3–8 的协议、冻结清单和归档结果全部保留在 Android 域，不因引入 Web 而改写。

排除（当前阶段）：真实 crash/功能回归缺陷发现、业务逻辑正确性、安全漏洞、性能、兼容性矩阵、多进程/native crash 归属、需要个人账户或真实外部服务状态的任务、无法从干净初态重复恢复的页面。只有另行建立已知功能回归、修复版本对照、去重判定和独立标签后，才允许把端点上升到缺陷发现。Round 4 的 Simple Calculator 与 Round 5 的系统应用只作工程/开发证据，不构成正式 benchmark 清单。

## 3. 范围内：WebUI Testing

纳入：本地可控、可重置的 Web 页面或站点；固定页面版本/构建摘要、浏览器版本、视口、语言、时区、网络规则和初始数据；通过 Playwright 截图、可见 DOM/可访问性节点和同一受限 `computer_use` 动作执行；终态由独立 DOM/可访问性断言核验，并在新上下文或干净状态重放。任务类型限定为有状态的功能流程：导航、同名控件消歧、动态列表、表单校验、阶段性状态依赖和错误恢复。

排除（当前阶段）：需要登录真实账户、第三方支付/邮件/短信、跨站 OAuth、实时协作后端、不可冻结的外部 API、生产环境数据、跨页面持久写入的业务副作用、文件上传下载、浏览器扩展与多标签并发。Web 页面必须可在独立浏览器上下文或本地 fixture 中从同一初态重建；依赖外部服务状态的样本记为不可比并保留排除原因。

Web 证据分三级，必须逐级报告，不得混称：① 本地 fixture，仅验证环境适配、动作结算、初态恢复与独立重放；② 本地冻结站点，用于机制筛查与提示/阈值开发；③ 独立站点家族，用于冻结后的前瞻性评估。当前仓库只完成第一级，见 `configs/web-mechanism-smoke.json` 与 `tests/test_environments.py`；第二、三级尚未运行。

## 4. 不在范围内（避免主张膨胀）

不研究被测系统内部的「多智能体应用」，不把 Android 与 Web 的轨迹合并训练出单一泛化模型，不比较不同基座模型的优劣，不主张货币硬预算，不把截图token、设备步数、浏览器操作、CPU 时间强行折算为同一标量。跨平台结论只覆盖两类 GUI 的**同一预算调度机制**，不覆盖 CLI、API、单元测试、代码仓库级修复、可访问性合规评分或视觉设计评价。

## 5. 平台内与跨平台分析口径

每个平台各自成立一个完整的配对实验：同检查点、同初态、同调用槽、同可见信息、同模型快照、同输出上限、同独立核验。主指标是预算内独立确认且去重的测试目标数，分母为预登记任务池；最小实际差异与预算档在打开测试家族结果前锁定。策略集合至少包含配置充分的单角色、带显式停止判断的单角色、自我复核、独立诊断、固定协作、规则介入、成本感知贪心与学习式选择；若新增 Web 专属动作，必须给 Android 同额度、同权限的可比对照或明确说明结构性例外。

跨平台汇总采用**分层**而非池化：先在每个平台内按应用家族等权计算配对差与不确定区间，再把两个平台的家族级效应作为分层结果报告，并显式标注平台。跨平台的交互项只回答「效应方向是否一致」，不能用来替代任一平台内的独立显著性。只有当两个平台都分别通过预登记门槛、且新家族均为未参与提示设计的隔离家族时，才可讨论机制层面的跨平台一致性。任一台未通过，结论收缩为「在已通过的平台与任务分布内成立」。

训练、验证、测试划分按平台分别冻结；允许共用代码、提示模板和特征 schema，但不允许用某一平台的轨迹去预测另一平台的留出结果，除非该跨平台迁移被单独预注册为研究问题。重复种子只估计同一应用内的波动，不增加独立家族数。

## 6. 统一预算与判定契约

所有平台共用分层 SQLite 账本：执行前按可执行上界原子预留，实耗结算，未知用量保留为未决承诺。主硬预算是模型调用数；设备/浏览器逻辑操作数作为同时生效的上限；token、时间、账单分别测量。Web 的一次浏览器上下文重建、页面导航、DOM 读取、截图与一次动作执行，和 Android 的一次 reset、UI dump、截图与 tap，统一记作一个逻辑设备操作，但该对应关系必须在协议的 caps 公式中冻结，不能事后按更省的一侧重算。复核、诊断、重规划、重放核验与失败重试全部计入同一预算。

判定器只在评估侧可见：执行者与复核角色只能看到截图、任务文本、可见历史与预算状态；终态断言、逐动作进度标签、修复版本对照与去重 ID 不进提示、不进决策特征、不进检索库。终态成功要求原执行与至少一次干净重放都满足断言；「先达标后被多余动作破坏」必须与「从未达标」分开记录。不可比、未尝试、预算停止、异常未解决都保留在分母。

## 7. 环境适配与版本冻结

代码侧引入平台无关的 `CheckpointEnvironment` 契约：恢复初态、读取可见节点、截图、应用一个受限动作、计算结构指纹、判定 oracle。Android 由 [environments.py](../src/budgetmas/environments.py) 的 ADB/UIAutomator 适配器实现；Web 由 Playwright 适配器或确定性内存 fixture 实现。两者共享 [ui_nodes.py](../src/budgetmas/ui_nodes.py) 的节点字段、定位、指纹与 oracle 语义；`mechanism.py` 只依赖该契约，不直接解析 ADB XML。旧 Android 协议不写 `platform` 时仍按 Android 读取冻结清单，保证归档结果可重算。

每个平台的冻结清单至少记录：平台、应用/站点家族 ID、来源与版本或构建摘要、入口与资源哈希、环境镜像/浏览器或模拟器版本、ABI/视口/语言/时区、网络规则、依赖版本、初始状态恢复命令、判定器版本、许可与使用限制、纳入/排除原因、划分种子、split 与清单哈希。Web 还需记录控制台错误与页面异常，但不得把它们当作无提示缺陷发现的标签。面向 agent 的 manifest 不含 oracle、缺陷对照表或修复信息。

许可与资产：APK、系统应用、Web 站点源码/构建产物、浏览器二进制、模型权重分别登记来源、版本、许可与再分发限制；未核验的许可保持 unknown，不打包含糊资产。本地 fixture 是工程验收资产，不是第三方数据集，也不是论文效果证据。

## 8. 最小推进顺序

1. 已完成：把 Android 专属节点/定位语义抽成平台无关契约，接入 Web fixture 与 Playwright 后端，新增 Web smoke 协议、离线运行入口、控制台 profile 和回归测试。此步只验证适配，不产生科研结论。
2. 下一步：选定本地可冻结的 Web 站点家族，按平台分别登记纳入/排除台账和许可，验证同一初态恢复、独立重放与预算 caps 在浏览器上的稳定性；对 Android 沿用已冻结清单。
3. 在每个平台分别执行 24 个配对检查点的机制筛查，使用既有门槛：至少 22 个通过初态与判定核验、协作相对自我复核至少 6 个独赢且来自至少 3 个家族、净赢至少 4、至少 6 个无正增益的可比检查点。若协作稳定不及自我复核，暂停扩大协作实验；若几乎所有任务都获益，先检验固定协作是否足够。
4. 分别通过门槛后，才按平台冻结训练/验证/测试家族、阈值与预算档，训练条件收益与成本头，并在**新的、未参与提示设计的应用家族**上做在线同预算对照与两类消融。
5. 只有两个平台各自支持主假设且分层交互方向一致、并为 Web 建立与 Android 同等级别的已知功能回归/修复对照后，才可将端点从功能任务完成扩展到缺陷发现。

当前状态声明：本仓库已有 Android 的开发诊断结果与 Web 的离线适配证据；**尚无 Web 真实站点运行、尚无跨平台前瞻性评估、尚无跨应用有效性结论**。README 中「开发拟合与离线回放不建立在新应用上的优势」继续适用于两个平台。
