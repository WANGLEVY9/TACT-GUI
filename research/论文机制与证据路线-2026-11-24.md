# 论文机制与证据路线

## 研究主张

在有状态的 GUI 功能测试中，同一个模型调用额度既能用于诊断，也能用于推进被测界面。额外复核可能阻止误操作或纠正方向，也可能占用完成流程不可缺少的执行机会。自适应调度是否有价值，取决于这种取舍能否用决策前状态预测，以及多个候选任务在总预算下竞争时，能否增加独立确认的功能测试目标。

候选论文贡献包括三个相连的部分。

1. 定义并测量复核相对直接续跑、独立诊断相对自我复核的两级净增量。在相同初态、调用槽、工具权限、任务和独立核验条件下复现。
2. 用可观测的界面与执行历史分别估计两级收益和资源成本。调度器明确检查执行槽、可执行成本上界和验证预留。任务级学习器只提供预测。
3. 以可恢复轨迹验证何时达标、何时失去达标。将重复操作造成的终态退化与真正的诊断增益区分开，再做新应用上的同预算在线对照。

## 相关工作与重叠

- FutureWeaver 已研究固定预算的多智能体推理资源分配和可调用协作模块。本项目仍需证明机制在状态会变化、结果依赖独立重放的 GUI 功能测试中具有独立价值。 [FutureWeaver](https://arxiv.org/abs/2512.11213)
- CATTS 已用 Web agent 的投票不确定性动态分配计算，说明统一增加每一步采样会遇到收益饱和。我们的候选变量是复核占用执行槽和可观察的流程进度，是否优于基于停滞或不确定性的规则仍需对照。 [Agentic Test-Time Scaling for Web Agents](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2026/EECS-2026-75.pdf)
- Self-Refine 使用同一模型反馈与迭代修正。它支持本项目采用同额度自我复核作为对照。ACL 的同计算预算实验也已比较自我复核、多智能体辩论及混合策略。角色增加与固定预算本身不足以界定新颖性。 [Self-Refine](https://arxiv.org/abs/2303.17651) · [Multi-Agent Reasoning Improves Compute Efficiency](https://aclanthology.org/2026.acl-srw.1/)

- ScenGen 已在 Android 上使用专门角色进行观察、决策、执行、监督与记录。GraphDroid 已用轻量启发式处理简单任务，并将复杂任务交给 GUI agent。正式对照至少要加入能在简单场景低成本完成任务的方法。 [ScenGen](https://arxiv.org/abs/2506.05079) · [GraphDroid](https://arxiv.org/abs/2609.10031)
- GUITestScape 已提出可交互的 Android 探索测试基准和过程能力评估。后续引入普通功能回归时，可先审核其任务和版本能否支持初态恢复和分支重放。 [GUITestScape](https://arxiv.org/abs/2605.29532)

这些是重点相关工作核对。其影响是收缩主张并加强对照，领域优先性仍需更全面核查。学位报告和预印本按各自发布形态使用。

## 此轮已实现的开发方法

八个开发检查点覆盖计算器、系统设置、时钟和文件四组。每组先冻结一条两调用、另一条三调用任务。每条轨迹分别运行直接续跑、自我复核、独立诊断，保持独立初态、模型快照、可见信息和总调用上限一致。两个额度分配在不同任务上，本轮只能描述分层结果，不能从两档差异推断额度的因果效应。时钟和文件与前期开发数据同源，所有组仍属于开发域。

记录决策前的 UI 节点规模、控件比例和重复标签比例，配合任务文本的简单统计和调用额度作为输入。按检查点完整配对，拟合三条正则化回归头，分别是直接完成分数、复核减直接、诊断减复核。三个分支的资源头在对数尺度上拟合。内部用留一应用交叉拟合检查组外误差，并将预测输入离线预算回放。回放使用同一检查点已实测的分支结果，按上界准入后扣实耗。回放在测过的有限候选中验证决策代码及开销，与实际新任务在线执行仍有区别。

诊断脚本对多次点击后仍失败的直接续跑，以及两种复核结局不同时的多次点击失败分支，从同一检查点重放两次，在每次动作后读取独立判定器。它验证观测到的执行轨迹是否先达标再退化。这个子集由终态失败选择，适合分析失败机制，不能估计整个任务池的发生率。任何未来以首次达标为主指标的实验都要提前登记，并且不能把隐藏判定器用于决策。

## 下一批确证实验的必要对照

1. 在同一任务检查点上交叉测试两和三调用额度。随机化两档及三分支的运行顺序，保留相同检查点 ID 下的所有重复。主交互量是同一检查点上两档的诊断减复核差值的差，以及复核减直接差值的差。按家族统计，禁止把重复运行当成新家族。
2. 增加直接续跑使用同一历史并明确防止重复操作的强基线。它只能通过可见状态判断停止。分别记录首次确认、终态确认和中间达标后退化。若复核优势被强停止基线吸收，报告停止机制的影响并放弃协作收益主张。
3. 扩展到 24 个配对开发检查点，预登记任务子类、候选数和排除规则。沿用前置筛查门槛。有足够应用级差异后冻结训练与验证协议。保持新的正式评估家族隔离。
4. 在验证集确定真正会阻止部分任务获准的聚合预算。在新应用的在线总预算中比较固定单角色、固定协作、强规则介入和学习选择。每个已确认目标都由独立判定器重放。报告跨家族配对差、未决验证、成本差与过程性消融。
5. 只有在引入同版本上下文可核对的已知功能回归、修复对照和去重判定后，才将结果上升到缺陷发现。当前端点是功能任务完成与保持达标状态。
