# 预算约束引导的多智能体自适应协作测试

2026-11-27

## 研究问题

给定一组可恢复的 Android/Web 功能测试目标与同一模型支出上限，测试系统应该在哪个时刻、为哪个目标调用哪种能力的模型，并给多少生成额度，才能增加独立核验的终态完成数？任务时延作为单独记录的次指标。评估以软件状态正确性为准。同样的方法也可用于一般 GUI 任务执行，功能缺陷发现需要另有已知回归、修复对照和去重规则。

假设是 **高能力模型的使用位置可以由 GUI 状态和剩余动作机会预测**。例如，当一个可见按钮唯一匹配已确认的意图时，规则或低成本模型可以执行。遇到同名控件、执行无进展、前后目标冲突，或需要在多个副目标间重新规划时，高能力模型可能改变随后可执行的动作。在预算接近耗尽时，诊断占用最后一个调用槽的机会成本也会上升。此前的计算器轨迹还显示，继续执行会让已达标的状态退化。

## 与现有工作的重叠

| 工作 | 已有机制 | 本研究需要额外验证的差异 |
| --- | --- | --- |
| [FrugalGPT](https://arxiv.org/abs/2305.05176) / [RouteLLM](https://arxiv.org/abs/2406.18665) | 在不同能力和价格的模型间级联或选择 | 选择会改变 GUI 状态及下一步可行集合。应使用有干预的配对分支来估计终态增益，并计入每次升级和重新观察 |
| [CATTS](https://arxiv.org/abs/2602.12276) | 用采样分歧在 Web agent 的执行步骤上选择性增加测试时计算 | 同样的计算还可以用来执行控件、诊断、停止或转投其他任务。额外采样本身也要从共同预算扣除 |
| [FutureWeaver](https://arxiv.org/abs/2512.11213) | 在固定预算下规划多智能体协作模块 | 候选区别落在可恢复 GUI 轨迹、独立重放、诊断挤占执行机会，以及已经达标的目标可能退化 |

异构模型、层级规划和帕累托求解均已有研究先例。候选贡献是发现并验证可观测的 **GUI 特有调度条件**，例如「升级只在有足够动作预算兑现诊断时带来净增益」，以及在相同总预算下确认这种条件可跨新应用重现。

## 状态、动作与收益

将用户意图表达为可审阅的任务契约 `g = (目标, 副目标依赖, 允许的副作用, 可见的停止条件)`。它来自任务文本与观察，复杂语义允许向强模型升级。独立判定器的具体 selector、隐藏预期值与回放标签仅在评估域可用。在线规则只能检查普通使用者能看到的状态，不能读取实验判定器。

状态 `x = (g, o, h, b)` 包括当前屏幕、可见节点 `o`、动作与已观察进展 `h`，以及剩余资源 `b`。难度采用决策前可计算的特征，如副目标依赖数、目标控件候选数、距离上次进展的步数、已发生的恢复、继续执行需要的最少动作数。没有可靠的难度估计时，使用缺失值及置信校验。判断难度应估计低成本分支完成目标的概率和升级带来的配对增量，任务文本长度只可作为基础对照。

动作 `a = (任务, 角色, 模型, 输出额度)`，执行类型包括可验证的机械操作、低成本模型执行、强模型诊断或重规划、停止并提交核验、暂缓任务。控制器在每次操作后观察 UI 状态。便宜分支可承诺某个小且可撤销的动作，强模型诊断返回可检查的子目标与当前可执行动作，其建议仍由工具权限和动作契约约束。

定义对同一检查点的两个合法续跑方案 (a) 与 (a_0)：

```text
Δp(x;a,a₀) = E[Y(a) − Y(a₀) | x]
Δc(x;a,a₀) = E[C(a) − C(a₀) | x]
Y(a) = 独立重放确认的终态完成
升级优先值 = Δp − λ·Δc
```

以同一原始状态、任务、视图权限、剩余调用额度及独立核验为配对条件。两个分支分别运行和重放，不从成功后的轨迹为未执行方案构造结果。对代价高的升级，可要求分组验证获得的保守增量达到预设阈值。置信与校准结果须在不同应用家族上核对。

可把同名候选的歧义量定义为其配对预测终态完成率的极差 `max p(a) − min p(a)`。只有通过任务契约且有可观测支撑的动作才能进入候选集合。极差小且所选动作预计可靠时，可以用低成本执行。极差小但所有候选预计会失败时，仍须估计重规划收益。MiniWoB++ 分支审计提供了一个两个候选都通过的实例；后续配对数据还需要包含真正有后果的消歧和执行受阻的实例，才能检验这个信号的区分力。

## 内外两层算法

1. **任务内。** 使用软件工程的前置条件、后置条件与有限状态转移，维护副目标进度和可逆性。对确定性控件优先尝试低成本操作。对歧义、循环、权限和异常缺失采用明确的升级/停止规则。维护 `L(x)`，即由可见证据得出的剩余执行动作下界。诊断后若额度无法容纳 `L(x)` 与必须的核验，诊断不可获准。错误或假停通过独立重放记入损失。
2. **任务间。** 对每个候选任务列出可行续跑配置，按可执行上界预留模型调用和操作预算，分别预测完成概率与 token 代价。每轮执行计划只采用第一项，已记录的实际开销结算后再求解。剩余预算越紧，低边际收益的升级越难获准。模板化任务的收益头可以先用收缩回归拟合，数据规模足够后再比较树模型与层级/分组校准。

本轮实现的外层求解器处理独立、可加的检查点和两项整数硬约束。每个任务最多选一个方案，允许跳过。动态规划按任务推进，网格坐标是调用和逻辑操作预留。每个坐标保留最大效用的选择。效用是预期完成数减去按权重 λ 折算的预测 token，效用相等时偏好更高的预期完成数与更少的 token。若已有方案在两项预留上都不高且在效用排序上不低，则其任意后续可行扩展同样支配被删方案。用前缀最大查询计算支配关系。固定 `λ` 得到以两项硬资源与该效用定义的非支配边界。完整的成功/货币/时延三目标经验边界需要在线多策略测量。

硬预算也包括诊断、重新观察与独立核验。未知用量保留预留。货币支出由冻结的模型快照价格表、计费维度与已观测用量计算。若供应商提供可执行的输入、生成及其他计费上界，可在调用前保守预留金额。当前实验只有调用数和逻辑操作数的硬预算，token 为记录与软偏好，历史数据全部来自一个 GUI-Plus 快照。

## 对照实验与扩展门槛

| 阶段 | 实验内容与验收 |
| --- | --- |
| 采集 | 同一 GUI 检查点采集规则、低成本模型、强模型、强诊断加低成本执行。控制界面观察、重置、权限、调用/生成上限；重复种子只能估计同家族内波动 |
| 识别 | 两个因素交叉。固定角色换模型识别能力差，固定模型换角色识别协作差。增加一个「同一模型换 token 上限」对照，区分能力与生成预算。若改变 DOM/视觉访问信息，单独消融 |
| 调参与部署门槛 | Android 与 Web 各自按应用/站点家族划分，任务模板的参数变化不能穿越划分。选择冻结预算入点和预设的最小效果差。若低成本方案已经稳定达标或增量头不胜过零增益/阈值基线，先调查差异的来源 |
| 事前评价 | 在新应用上比较固定廉价、固定强模型、按置信度升级、固定协作、同一预测器的贪心/预算优化。主指标为同预算下独立确认的终态数量。另一端点考察质量达到预设阈值时的支出；同时报告未决、覆盖、时延、按家族配对差 |

Android 先对接 [AndroidWorld](https://github.com/google-research/android_world) 的原生判定和重置接口。本轮只使用已有 Android 真实归档做开发回放。Web 已对接 [MiniWoB++](https://github.com/Farama-Foundation/MiniWoB-plusplus) 三个任务的原生网页，用固定种子与原生奖励验证运行链路。正式 Web 候选可从 [WebArena](https://webarena.dev/og/) 可自托管站点中筛选可冻结、可重置的多步功能任务，再做站点家族留出。两端各先完成原生判定对照和同模型交叉，验证过的动作与预算约束才进入跨模型采集。

本轮实验记录和复现入口见 [Round 10](../docs/ROUND10-FRONTIER-AND-WEB.md)。
