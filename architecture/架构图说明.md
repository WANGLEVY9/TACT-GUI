# 固定预算下的自适应多智能体测试：完整候选架构

该图描述候选技术路线，模型、组件和优势尚未得到实验验证。实线表示主要数据或控制流，虚线表示可选模块、模型发布或实验反馈；图中训练模块不意味着必须全部实现。

## 核心对象与接口

- 状态：测试任务及依赖、环境与历史、Agent 配置、可用预算、待验证证据。
- 动作：选择测试任务、Agent / 模型 / 协作配置和执行预算上限，必要时继续、切换或停止。
- 反馈：执行轨迹、实际成本、状态变化、异常线索、复现与验证结果。
- 硬预算：账本须原子预留可执行上界，且所有实际支出不得超过预留；包括并发、重试、调度、通信和验证。若外部计费无法保证上界，不应声称绝对货币预算保障。
- 反事实目标：比较不同动作时应明确相同起始状态、总预算口径、后续策略及最终收益；随机化、状态隔离和充分覆盖是识别的重要条件，重复执行本身不自动证明因果结论。

## 实施顺序

1. 确定一种可重复的测试任务、确认标准和成本单位，检查候选测试底座的可恢复性与可改造性。
2. 实现统一成本账本、执行封顶、状态日志和固定配置；先跑通端到端反馈。
3. 在可恢复状态下对不同配置和预算进行受控比较，检验收益差异与预算重分配需求。
4. 建立固定 / 动态预算与固定 / 动态协作配置的 2×2 实验，并加入有竞争力的成本感知基线。
5. 根据实际数据和误差分析逐步选择价值模型、结构化策略与前瞻模块；离线训练和在线强化学习均依赖数据与收益证据。
