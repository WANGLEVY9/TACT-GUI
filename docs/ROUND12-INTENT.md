# 第十二轮 实验意图驱动的 GUI 调度

## 执行契约

注册协议可选用 `mode: intent`。它消费任务原文和当前可见节点。第一版只自动执行语法可完整验证的显式点击、点击顺序及禁止点击约束，支持中英指令和按钮/链接角色。目标和禁止项发生冲突时进入澄清。有序步骤超出注册动作槽时，在第一步之前暂缓。

每次点击前重新读取可见控件。用用户指定的标签和角色匹配启用控件，检查坐标范围、重复标签与遮挡。Web 额外检查点击中心实际命中的元素。可执行目标唯一时用现有坐标协议直接执行。任务步骤结束后走原有独立重放，报告保留执行是否符合契约以及终态是否通过这两个信息。

不支持的原文可配置一次 Qwen-Flash 或 Qwen-Plus 语义解释。在输出上限内请求结构化 JSON，校验步骤和限制所引用的证据是否原样出现于用户指令。模型候选只进入待澄清记录。候选可能正确保留一段引文而解释错误，证据检查只验证出处。控制台显示待澄清原因、问题、原始候选和已执行动作。模型调用、观察、截图、动作和重放都使用现有账本。

## 开发验收

| 验收 | 实际结果 |
| --- | --- |
| MiniWoB++ 原版 Chromium | 唯一按钮、关闭对话框、有序按钮共 3 个通过独立重放。同名按钮和未支持的颜色定位共 2 个停在澄清。5 个实例模型调用为 0，56 个逻辑操作已结算。 |
| Android 冻结计算器 | 4 个实例均能恢复和重放。等号任务通过；中文指令按序点击 `C` 和 `8`，终态未通过。禁止项冲突进入澄清，3 个步骤只有 2 个槽时暂缓，两者均未点击。 |
| 真实语义网关 | 对颜色任务调用一次 `qwen-flash-2025-07-28`。返回了带原文证据的「定位橙色方块、点击」候选。记录保留待澄清状态，点击数为 0，目录价估算为 ¥0.0001389。 |

中文用例暴露了动作标签与效果之间的差异。点击 `C` 后，截图中 `7+3` 变成 `7+`。这个控件的一次短按未清空表达式，随后点 `8` 仍无法满足独立的终态判定。本轮保留该负结果。支持语义终态后，应另行记录「用户明确要求的效果」和「用户明确指定的动作」，允许在经确认的动作范围内根据可见状态重规划。独立评估器仍使用隔离的判定条件。

这些样本验证了选择性执行、资源计量和报告链路。覆盖范围只含指定语法和本轮部署环境。语义网关目前只有一次真实请求，不用于估计一般意图理解准确率。

## AI 方法与后续对照

意图与控件落地借鉴 [SayCan](https://arxiv.org/abs/2204.01691) 将语言目标与环境可执行能力共同约束的思路。对无法确定的状态采用[选择性预测](https://proceedings.mlr.press/v97/geifman19a.html)的评估方式，分别测覆盖率和被自动执行样本的意图错误率。

下一批数据按同一语义目标生成多种原文表达，包含否定、顺序、条件、指代、约束冲突以及实际控件效果不足。用同一可恢复状态配对「规则定位」「文本复核」「视觉诊断」的选择。标签分别标注意图、许可范围、控件、终态和费用。对进入自动执行的样本估计意图错误率，同时保留全部注册用例作为端到端完成率的分母。

下一版用小型监督模型估计两项量：当前契约与用户语义不一致的风险，以及诊断相对直接执行在剩余额度下的配对终态增益。训练和校准分别按应用家族切分。任务内先筛除预算不足或权限不明的候选，任务间再把剩余候选的预测收益与费用交给已有预算分配器。角色模型的自报置信度不作为风险保证。
