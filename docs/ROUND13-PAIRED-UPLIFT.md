# 第十三轮 配对诊断增益、分组校准与预算回放

## 实验协议

Android 使用冻结的系统应用和计算器，覆盖 4 个应用家族、10 个预登记检查点。两个检查点从已执行的非空历史继续，包括计算器短按清除后的 `7+` 和已进入网络设置页的状态。Web 使用原版 MiniWoB++ 的 8 个任务模板，每模板两个种子，共 16 个实例。模板内重复不增加家族数。Web 仍属于同一公开基准。

每个检查点恢复后随机排列三个分支。Flash 直接执行是低成本基线；Flash 复核与 GUI-Plus 复核都由同一个 Flash 执行者继续，调用槽和输出额度一致。独立重放核验起始结构、可见状态指纹和终态。当恢复验收、分支配对、用量或原始截图任一项不满足时，报告保留该检查点及原因。本轮采集的是注册恢复态上的受控继续分支。

## 模型与预算

以可见节点统计、任务文本统计、已登记前缀长度和剩余调用槽为输入。对每个训练家族等权拟合收缩回归。直接分支拟合完成率，另外两个头分别拟合「Flash 复核减直接执行」和「GUI-Plus 复核减 Flash 复核」的配对终态差，后者即诊断升级增益。成本头使用 API 记录与北京目录价得到的轨迹费用。任何核验标签、末态、模型回答和费用均不进入决策前特征。

每折留出一个完整 Android 应用或 Web 模板。剩余家族按固定种子拆到训练与校准，留出家族的结果仅用于一次回放和评估。在三个固定阈值 0.4、0.6、0.8 中，用单侧精确二项上界和 Bonferroni 修正校准。统计单位为至少有一个候选通过门控的家族；只要其中任一通过候选未达标，该家族记一次错误。这个事件上界覆盖预算调度随后选出的候选子集，所需独立性和同分布假设在开发集上没有确证。指标衡量独立重放的终态错误，意图解析错误仍需单独人工标签。方法借鉴 [选择性预测](https://proceedings.mlr.press/v97/geifman19a.html) 与 [Learn then Test](https://arxiv.org/abs/2110.01052)。

预设家族错误率上限 20%，单折置信度 90%，三个阈值分别使用 `δ/3`。即使没有观察到错误，至少也需要 16 个通过门控的独立校准家族才能过线。没有合格阈值时，校准分配器不自动执行。

未经校准的学习分配器与校准版分别将候选提交给现有精确分配器。效用为预计完成概率减去 8 倍的预测费用（元）。调用和逻辑操作按上界准入，然后依已观察分支的实耗扣账。费用项是软偏好，报告的实测费用也只是目录估算。紧预算为家族内总上界的一半，逐资源至少允许最低的单任务上界；全预算允许整个注册池。固定分支以相同预算作对照。

## 实验结果

| 指标 | Android | Web |
| --- | ---: | ---: |
| 完整配对 / 登记 | 7/10 | 16/16 |
| GUI-Plus 升级独赢 / 平 / 独输（相对 Flash 复核） | 0 / 7 / 0 | 2 / 11 / 3 |
| 家族等权增益 MAE，学习 / 零增益 | 0 / 0 | 0.378 / 0.313 |
| 紧预算完成数，学习分配 / 最强固定对照 | 3 / 4 | 4 / 5 |
| 全预算完成数，学习分配 / 最强固定对照 | 3 / 5 | 9 / 11 |
| 达到校准准入线的留出折数 | 0/4 | 0/8 |

Android 的最强固定对照是 Flash 复核和 GUI-Plus 复核，两者打平。在同一可比任务池、全预算下，Flash 复核目录估算 ¥0.010709，GUI-Plus 复核估算 ¥0.037246。Web 全预算下，直接 Flash 确认 11 个，费用 ¥0.004630，学习分配确认 9 个，费用 ¥0.004731。现有任务统计与 UI 几何规模等特征没有提供足够的升级信号。计算器清除后的非空前缀也没有出现升级收益。后续应优先收集可见进展、选项后果分歧和动作可行性，保留足量独立校准家族。

排除的 Android 检查点为电池页和计时器的可见状态不匹配，以及文件菜单的模型请求异常。原始结果与未决预留均保留。两端共验证 184 条返回收据对应的截图哈希，182 次调用已顶层结算。Android 账本保留 9 次调用额度，Web 无未决。已返回收据合计目录估算 ¥0.0969311，未定请求的费用未估计。

## 复现

```sh
PYTHONPATH=src python -m budgetmas.paired_uplift \
  results/round13-uplift/android /tmp/tact-android-uplift.json
PYTHONPATH=src python -m budgetmas.paired_uplift \
  results/round13-uplift/web /tmp/tact-web-uplift.json
```

此步骤不调用外部模型。运行目录中的协议、报告与模型调用前截图是输入。分析验证快照、角色、生成额度、起始状态、终态及截图哈希，输出完整的拟合参数、家族划分、阈值曲线和分配决策。原始模型运行入口沿用 [Round 11](ROUND11-ALIBABA-ROUTING.md) 中的 Android 和 Web 命令，替换为 `configs/android-paired-uplift.json`、`configs/miniwob-paired-uplift.json` 和新的输出目录。Web 的模型配置已经写入协议，可省略第二个配置参数。
