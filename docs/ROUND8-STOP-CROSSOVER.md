# 同检查点的停止判断与预算交叉试验

2026-11-24

选取三个开发检查点。计算器和计时器来自上一轮已观测到终态退化的任务，系统设置包含两个连续的导航步骤。该选择用于诊断，三个检查点均已参与早期开发，不属于独立测试集。

每个检查点运行两次和三次模型调用额度。额度顺序在运行前平衡，分支在每个额度内按固定种子打乱。四个分支为直接续跑、带明确停止判断的单角色续跑、自我复核后执行、独立诊断后执行。四个分支使用同一模型快照、任务、观察接口和输出上限。停止判断仅改变单角色提示，使用当前截图和可见操作历史。自我复核和独立诊断各占一个调用槽。

为缩短真实执行时间，三个应用分别运行在三个隔离的 Android 34 模拟器。每个应用的全部分支和两个额度在同一设备上运行。所有设备均须通过同一冻结清单核对，多个设备共享一次试验的 SQLite 总账本。两档上限交叉的顺序和设备映射分别保存在注册 JSON 和本地运行记录中。

每次执行动作后，由独立 UI 判定器记录是否符合目标。记录只用于评估，提示、停止决策和准入均看不到判定结果。干净恢复后重放全部动作，再记录每步及最终状态。只有原执行和重放的逐动作结果一致，才统计首次达标和随后失去目标。最终成功仍要求重复验证终态。额外判定读取预留为两次轨迹各最多一个 UI 读取每执行动作。设备开销含独立测量，不能直接解释为只部署策略时的操作开销。

复现实验使用包内入口与冻结应用清单。

```sh
PYTHONPATH=src python -m budgetmas.mechanism configs/android-stop-crossover.json \
  results/round5-android/manifest-v2.json --device-map path/to/device-map.json \
  --out results/stop-crossover
PYTHONPATH=src python -m budgetmas.horizon analyze configs/android-stop-crossover.json \
  results/stop-crossover/report.json results/stop-crossover/interaction.json
```

也可以用 `--serial` 在一台专用模拟器上串行执行。设备映射为应用组到 ADB 序号的 JSON 对象。注册方案的总模型调用上限为 60 次，逐动作的独立核验不额外调用模型。

## 原始运行

共登记 3 个检查点、6 个额度条件和 24 个分支。设备故障导致计时器两次额度的直接续跑在发起模型调用前超时，以及设置三次额度的独立诊断在两次调用后因设备操作错误停止。原始记录仍保留。其余 22 个分支已判定，只有计算器检查点满足两档四臂齐全的主分析条件。原始运行记录了 55 次模型响应，顶层账本结算 53 次并保留两个异常分支的 5 次调用承诺。承诺是上限，含已见但尚未顶层结算的调用和未用额度。

计算器八个分支均曾获得目标值，最终仅两个分支通过。两次额度下，自我复核和独立诊断保持了结果。三次额度下四个分支均先达标后失去目标。显式停止提示的单角色在两档均失去目标。这是一个重复等号检查点的受控观察。跨检查点、跨应用的停止能力需要在更多任务和种子上检验。

技术重试仅接受原始未解决且属于设备错误的分支。复用原设备、起始条件、模型和额度，ADB 超时由 20 秒增至 40 秒。每分支最多重试一次，成功或未完成的已判定结果一律不重跑。补充结果写入独立目录并校对初态，原始报告与主分析保持只读。重试费用单独记账。

## 补充分析

两个技术重试均完成了初态和独立重放核验。纳入这两个结果后，三个检查点均可计算交互量。重试用了 5 次模型调用、14,941 token 和 29 个逻辑设备操作，重试账本无未决项。原始运行的 55 条已返回请求共 162,098 token，原始账本保留的技术故障承诺不因重试改变。

| 检查点 | 调用上限 | 直接续跑 | 停止提示 | 自我复核 | 独立诊断 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 计算器乘法 | 2 | 0 | 0 | 1 | 1 |
| 计算器乘法 | 3 | 0 | 0 | 0 | 0 |
| 时钟计时器 | 2 | 1* | 1 | 1 | 1 |
| 时钟计时器 | 3 | 1 | 1 | 1 | 1 |
| 从设置进入互联网 | 2 | 1 | 1 | 0 | 0 |
| 从设置进入互联网 | 3 | 1 | 1 | 1 | 1* |

星号表示技术重试。两档各聚合三个任务，所有策略都为 2/3，应用之间的机制不同。计算器上，复核随着额度增加由成功变为随后退化。设置任务上，第三个调用给复核分支补足了第二个执行槽，终态由失败变为成功。两种复核在所有可比条件下的终态相同。停止提示与普通续跑的终态也相同。结论限于三个为机制筛查而选的开发检查点，每个条件只有一条轨迹。

下一轮可在独立应用上比较不读取隐藏断言的状态判断模块，控制额外提示与真实状态进展本身的影响。可把首次达标、终态达标、达标后失效与验证成本同时入账。计算器结果提示应单独考虑已达标后的动作风险，设置结果提示复核决策需保留完成剩余步骤所需的执行槽。

原始运行、主分析和技术重试分别保存在 `results/round8-crossover/live/report.json`、`results/round8-crossover/primary-interaction.json` 与 `results/round8-crossover/recovery/sensitivity.json`。两套账本均通过上限审计。56 项测试通过，专用模拟器均已关闭。
