# 多应用功能测试与学习调度试验

2026-11-23

## 研究设计

本试验用 Android 模拟器中的实际应用验证应用分组、真实运行轨迹、CPU 训练和等预算在线评测。每个任务提供一段操作意图和候选界面名称，结果判定依据应用的 UI 层级。主定位器尝试首选短语，协作定位器在找不到元素时尝试别名。两种模式共享观察接口、任务描述与验证器。额外加入一个单角色使用全部别名的对照，以区分别名搜索能力和角色分工的作用。前两种配置是学习型策略的候选动作。当前试验的角色是可复现的规则测试角色，复用上一轮的 Android/预算框架。

控制器在每个应用的相同任务和资源上限下比较四种策略。决策动作是任务与角色配置的组合。每次试验先预留执行和验证的最大开销，实际支出从同一 SQLite 分层账本结算。一次角色调用计一个 agent call，一次逻辑 reset、UI dump 或 tap 计一个 device step。总耗时包括应用重置、执行和验证，记录为观测量。

独立验证读取原始终态，重新启动应用并重放坐标序列，再检查终态和重启后的结构指纹。起始状态已满足目标、起始状态结构变化、重放不一致或基础设施故障均标为未解决。控制器比较各策略实际尝试过的同任务起始状态。任务完成和未尝试均保留在评估分母。遇到未决预算，保留承诺并停止该策略在该应用的运行。

## 从 SOCRATES 复用的训练方法

已只读核对 SOCRATES 本地源码提交 `4e9a99a5`，包括 `socrates/modules/cost/features.py`、`model.py`、`training.py` 和 README 里的 `socrates-fit`。借鉴的是按任务和重复内容分组、在训练折内选择、CPU CatBoost 对数成本回归、原单位 MAE、模型与分析元数据分别持久化。SOCRATES 的标签是人工审查耗时，本试验的标签来自设备执行。已有 SOCRATES 模型和人工数据留在原项目。

BudgetMAS 的 7 个特征在决策前可用，包括工作流长度、含备选短语的步骤比例、角色配置及交互项。编码不包含应用身份、结果字段或判定条件。任务完成分数用正则化线性模型拟合，预测限制到 [0,1]，按训练应用留一交叉验证的应用等权 Brier 选择正则化系数。调用数、设备操作数和总耗时分别用 CatBoost 1.2.10 的 CPU 回归拟合 `log1p(cost)`，在训练应用留一交叉验证中用原单位的应用等权 MAE 选树深度。保存训练数据 SHA-256、折名单、超参数、验证误差和 CBM 的 SHA-256。时长模型用于预测诊断，实际决策使用两种有硬上限的资源。

学习型策略在预算可行候选中最大化 `预测完成概率 − 0.045×预测角色调用 − 0.018×预测设备操作`。系数是本轮先设定的工程权重，随模型记录。模型参数和权重在测试应用执行前冻结。小样本误差用于检查数据链路和明显偏差，尚无概率校准或跨应用泛化保证。

## 环境与复现

环境为专用 `BudgetMASPilot` Android 34 ARM64、Google APIs 镜像，常用系统包由同一镜像提供，计算器使用官方发布的 5.12.0 APK。包版本和 Android build fingerprint 写入冻结清单。系统包的开源及再分发许可未核对。所有任务仅在无个人账户的本地模拟器执行。

计算器 APK 取自上一轮的官方 release，SHA-256 为 `092629deaeaaea824dbf0cd824989e80b498b1fa07ad5b4c3e744fc64ce5ab2f`。系统设置和文件等应用从入口重新启动，时钟与计算器先清理应用数据，拨号应用回到 Favorites。通讯录授权设置仅在本轮专用模拟器内完成。重新执行试验前应首先核对专用设备及包版本。 [计算器官方 5.12.0 发布页](https://github.com/SimpleMobileTools/Simple-Calculator/releases/tag/5.12.0)

原始清单、采集、模型与对照日志留在 `results/round5-android/`。首轮采集保留了时钟标签页状态不稳定、通讯录权限阻塞和个别重放不一致。用于后续运行的第二版清单登记了时钟清理和拨号的起始标签，另完成专用设备中通讯录权限准备。任务和标签先经过同一模拟器试验开发，测试应用在模型训练中按组留出，任务设计层面曾参与 UI 探查。

建立和启动同名专用 AVD 时，使用 SDK 的 `avdmanager create avd --name BudgetMASPilot --package 'system-images;android-34;google_apis;arm64-v8a' --device pixel_6`。启动参数为 `-avd BudgetMASPilot -port 5582 -no-window -no-audio -no-snapshot -no-metrics -gpu swiftshader_indirect`。等待 `sys.boot_completed=1` 后，在该设备安装本次固定 APK，设置窗口、转场及 animator 三项动画比例为 0，再运行 README 的四个命令。通讯录需在专用设备完成本地 Skip 启动流程并检查系统权限对话框。若仍受阻，结果会保留为未解决，每个偏差都需要记录。

训练进程使用了本机 SOCRATES 虚拟环境中已存在的 CatBoost 1.2.10，依赖版本也已写入本仓库的可选安装项。成本的 60 棵树、学习率、L2 和单线程等设置在代码中冻结。只用该环境的 Python 与依赖，实际训练代码、数据读取和模型产物均属于 BudgetMAS。

## 已冻结的数据与训练结果

| 数据集 | 应用家族 | 任务 | 采集后用于对应阶段的记录 |
| --- | --- | ---: | --- |
| 训练 | 时钟、通讯录、文件 | 6 | 时钟和文件的 8 条实际 UI 执行记录纳入拟合，通讯录 4 条保留为未解决 |
| 验证 | 计算器 | 2 | 4 条执行记录均通过标签准入 |
| 测试 | 设置、拨号 | 4 | 固定模型后的同预算实时对照 |

第二版训练与验证采集共 16 条。训练应用包含 6 条任务完成、2 条可重放的未完成和 4 条未解决。验证应用包含 3 条完成和 1 条未完成。通讯录 4 条未解决均无可用的起始状态证据，整对排除且未更换其应用分组。

两折留一应用训练选择了成功模型的正则化先验 0.1，以及三个成本头的树深 2。计算器验证集的 Brier 为 0.0947，角色调用、逻辑设备操作及总耗时 MAE 分别为 1.81 次、2.52 次和 2.05 秒。纳入拟合的任务均为一步操作，计算器含四步流程，这些误差体现了任务长度外推的限制。各校验的确切数值及两折选型结果保存在 `results/round5-android/model-v2/model.json`。

## 同预算留出实验

设置和拨号各有 2 个任务。每个策略在每个应用均有 8 次角色调用和 26 次逻辑设备操作的上限。全程共运行 16 个任务试验。4 个任务在四种策略之间的起始 UI 结构指纹一致。各次结果均完成独立重放核验，各策略无超预算及未决预留。

| 策略 | 独立核验完成数 | 角色调用 | 逻辑设备操作 |
| --- | ---: | ---: | ---: |
| 固定主定位器 | 2/4 | 4 | 34 |
| 固定双角色 | 4/4 | 8 | 40 |
| 固定单角色搜索全部别名 | 4/4 | 4 | 40 |
| 学习式选择 | 4/4 | 8 | 40 |

学习策略四次均选择了双角色。它与固定双角色取得相同的任务完成数和资源支出，单角色全别名对照以一半的角色调用取得相同完成数。这组任务支持将效果归因于找到备选定位名称，尚无证据支持角色分工或动态选择存在额外收益。留出样本仅两应用四任务，且未观察到预算造成跳过任务，因此不能据此判断预算瓶颈下的调度效果。角色调用计数是试验定义的资源单位，不代表 LLM token 或真实货币支出。

完整记录位于 `results/round5-android/comparison-v2/comparison.json`。运行后另核对模型元数据 SHA-256、各策略预算上限、起始指纹及未决承诺。Python 3.12 下 45 项单元和集成测试通过。
