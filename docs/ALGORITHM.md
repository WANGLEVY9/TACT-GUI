# 预算约束多智能体测试：数学定义与实现映射

本文件描述本仓库实现与研究候选，未声称方法新颖或优于已有工作。2026-11-23。

## 1. 目标、观测与动作

令决策前可观测状态为 s_t，剩余资源向量为 b_t。动作 a=(任务 u，协作配置 c，额度 q)。测试执行模型和收益/成本估计器分离。配置是 proposer、可选 critic、执行环境、独立 verifier 的组合；增加角色本身没有收益保证。

收益 r_t 是预算内首次独立确认的去重缺陷数。终止、不可判定、角色否决、基础设施失败分别记录。验证器标签不进入 agent 观测。目标是最大化 E[sum r_t]，约束每个资源维度 sum actual_t,k ≤ B_k，并满足任务依赖、角色冲突和环境恢复条件。

资源不互相换算；模型调用次数、环境交互、时间、计费分别定义。如果外部调用无法约束实际资源上限，则对应维度只能测量或软约束。不能将预测成本的置信上界当可执行物理上界。

## 2. 动作条件多头模型

特征 φ(s,a) 必须仅用决策前可见信息，包括归一化剩余预算、任务/配置编码、历史验证结果、已观测依赖和环境状态。当前编码由调用方提供，固定维度；还没有自动图特征构造。

`models.BayesianHead` 实现：

A = λI + Σ φ_i φ_iᵀ / σ²

h = Σ φ_i y_i / σ²

μ(φ) = φᵀ A⁻¹h，u(φ) = sqrt(φᵀ A⁻¹φ)

采用 Cholesky 分解和线性求解，避免显式求逆。保留完整协方差以处理相关特征。这里 σ² 是固定噪声参数，不是由样本学习的方差；不自动提供概率校准。

`JointModel` 为收益和每种资源分别训练一个 head，成本监督为 log(1+c)。输出 median≈expm1(μ_c)，上界代理≈expm1(μ_c+βu_c)。这是模型假设下的后验 log-cost 位置区间，未经验证集校准时不可解释为真实分位数。收益 head 采用线性高斯基线，计数/二元输出不应直接解释成合法概率。

`training.fit` 强制非空训练/验证集、项目组不相交、轨迹 ID 唯一、标签已判定。模型 artifact 包含数据 hash、项目组、维度和验证 MAE，并支持读取。当前缺少自动特征缩放、超参搜索、交叉拟合和校准流程；正式训练前须补齐这些协议。标签 provenance 仍由采集端保证。

## 3. 保守决策与批量选择

每个动作的评分为

v(a)=μ_r(a)−βu_r(a)−Σ_k λ_k ĉ_upper,k(a)。

β≥0 为保守系数，λ_k 为资源影子价格。允许空计划，避免所有候选预测净收益不正时强制执行。开发期的探索另用 epsilon 混合策略，记录精确 propensity；测试期默认冻结模型，不能混入训练期探索或不经声明地更新模型。

`BudgetPlanner` 在最多 20 个候选上进行分支限界，求解当前批次的有限优化：

max_z Σ_a v(a) z_a

subject to Σ_a q_a,k z_a ≤ b_k；同任务至多选一个配置；共享 worker 不能冲突；Σ_a z_a ≤ slots；依赖必须在该批开始前已完成。

使用正分数剩余和作乐观分支上界。实现对该有限候选集合及可加目标是精确枚举剪枝，不等于全 campaign 全局最优。它没有学习动作间互补或长期状态转移，不能称为完整 POMDP 最优求解器。候选过多时显式报错而不偷偷丢弃候选；需要上层可审计的候选剪枝。测试以独立暴力枚举对照验证最优值。

`PrimalDual` 更新

λ_(t+1),k = max(0, λ_t,k + η(actual_t,k − target_t,k)/max(1,target_t,k))。

这是资源消耗节奏的可解释基线。`Campaign` 依据剩余额度及剩余轮数产生 target，并把价格回传下一次规划。这里尚无任意状态下的 regret、收敛率或约束最优性证明；真正预算保障来自可执行上界与账本准入。

## 4. 执行和验证闭环

`TeamExecutor` 先预留 proposer、critic、环境执行和独立复现的总额度，再逐角色执行并检查实际用量。角色不能自行扩大额度。角色异常时整笔未决预留保留；不会自动假定失败调用免费。正常结束释放剩余额度。未知使用量需外部核对，当前没有自动核对任务。

角色任务必须在回调内部遵守 quota；Python 回调本身不是沙箱。真实 SDK、模拟器和进程适配器仍须设置可执行限制、超时和进程回收。当前执行器顺序调用角色，不能被同一进程多线程共享；账本支持多个进程竞争预算，journal 只有单写入者。

`Journal` 记录试验、决策、角色资源、失败和验证事件，并链式散列检测意外损坏；没有外部签名，不是抗主动篡改的安全日志，也未实现断电恢复事务。费用表以 SQLite 为准。

本地 `fixture` 是一个可执行的购物车故障程序和修复版本：proposer 生成动作、critic 检查合法性、环境执行、独立 verifier 在新实例重放并比较 buggy/fixed。连续两次发现同一故障奖励分别 1 和 0，检查预算和去重。该故障为人工构造，仅验证模块交互，不用于论文效果。

`Campaign` 将联合模型规划器与执行器连接，记录当前可见分数和资源价格，按任务去除已消费机会，显式报告停止原因。每个任务从独立初始状态启动，依赖仅表示验证完成元信息，不自动继承前一任务的 GUI 状态。

## 5. 离线估计和统计

`evaluation.logged_policy_value` 实现单步 IPS 与 doubly robust：

w_i = π(a_i|x_i)/p_i

V_IPS = mean(w_i r_i)

V_DR = mean(q_π(x_i)+w_i(r_i−q(x_i,a_i)))。

同时报告有效样本量 (Σw)²/Σw² 和最大权重。要求覆盖、正确选择概率、固定目标策略；q 需通过组级交叉拟合产生。代码只能验证数值合法性，不能证明这些识别前提。此函数不估计有状态干扰的任意多步 campaign 价值，不能用来替代随机配对真实运行。

`paired_cluster_interval` 先在每个应用内平均随机种子的配对差，再对应用均值做聚类 bootstrap。当前目标是应用等权均值，不是所有缺陷加权均值。至少两个应用才能运行；两三个应用的区间仍不可靠，不能凭 API 可计算就认为统计样本足够。

## 6. 下一步有价值的扩展

1. 将真实 Android adapter、GUI-Plus 多轮动作和 crash replay verifier 接入相同 contract；评估缺陷标签与固定版本。
2. 固定候选配置、动作特征 schema 和采集随机化方案，记录真实资源与未解决试验；模型训练前冻结应用分组。
3. 对照完整协方差线性模型、树模型与动作条件神经深度集成；以组级验证选择和校准，不能按模型复杂度直接确定优胜者。
4. 在观察到真实任务依赖和共享状态失效后研究图表示；有足够轨迹后研究有限前瞻及联合增量价值，分别消融。
